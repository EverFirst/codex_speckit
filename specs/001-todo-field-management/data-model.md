# Data Model - TODO Advanced Field Management

## Entities

### TodoItem
| Field | Type | Nullable | Default | Notes |
|-------|------|----------|---------|-------|
| id | TEXT (UUID string) | No | n/a | Primary key generated by service layer. |
| title | TEXT(200) | No | n/a | Existing required field. |
| description | TEXT(2000) | Yes | null | Existing optional field. |
| completed | BOOLEAN | No | false | Stored as 0/1 in SQLite, toggled via service logic. |
| due_date | DATE | Yes | null | ISO 8601 `YYYY-MM-DD`, past dates allowed. |
| priority | TEXT(10) | No | 'medium' | Enum low/medium/high, default applied by DB and service. |
| category | TEXT(50) | Yes | null | Trimmed string, blank resets to null. |
| tags | TEXT (JSON array) | Yes | null | JSON array of up to 10 lowercase strings, preserves order. |
| created_at | DATETIME (TZ) | No | now() | Set by service/repository. |
| updated_at | DATETIME (TZ) | No | now() | Updated on every mutation. |
| completed_at | DATETIME (TZ) | Yes | null | Mirrors `completed` transitions. |

### TagAssignment (logical view)
| Field | Type | Nullable | Notes |
|-------|------|----------|-------|
| todo_id | TEXT | No | References `TodoItem.id`. |
| tag | TEXT(20) | No | Lowercase item stored inside JSON array. |
| ordering | INTEGER | No | Implied by JSON index when serializing back to clients. |

This view is not a physical table but represents how service/repository logic should treat the JSON list when enforcing uniqueness and order.

## Relationships and State
- `TodoItem` is the sole persisted entity; tags remain embedded but are treated like a child collection when validating or updating.
- `completed_at` continues to depend on the `completed` boolean (already enforced in Feature 001) and does not interact with the new fields.
- No additional foreign keys are required; repository consumers access metadata exclusively through the existing `todos` table.

## Validation Summary
- `priority` limited to `{'low','medium','high'}`; default to `medium` when missing.
- `due_date` accepts any ISO date string; reject malformed or impossible dates.
- `category` trimmed and rejected when length > 50; trim-only input counts as removal.
- `tags` length 0-10; each entry trimmed, lowercased, limited to 20 characters, duplicates rejected after normalization.
- All new fields remain optional in requests and may be `null` in storage/response payloads for legacy items.
